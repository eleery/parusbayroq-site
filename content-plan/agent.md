# Ежедневная статья — порядок работы

Запускается каждый день утром (по Ташкенту) задачей по расписанию в этом же чате. Владелец утверждает каждую статью; без его «публикуй» ничего не выходит на сайт.

Факты — только из `knowledge.md`. Правила текста — там же. Цены — из `src/lib/prices.mjs` (в статье — карточки `<div data-price-table="parus,flag"></div>`).

## 0. Проверка очереди
- Если в `topics.md` уже 3 темы со статусом [~] (ждут одобрения) — новую не писать. Коротко напомнить владельцу, какие статьи ждут, со ссылками на документы.
- Тема с пометкой «спросить владельца» — пропустить, задать вопрос в отчёте, взять следующую.

## 1. Материал
- Поиск (WebSearch, standard) по теме на русском, узбекском и английском: что пишут другие, какие вопросы задают покупатели, какие картинки ставят.
- Референсы для картинок: 2–3 фото по теме (через web-fetch). Разобрать композицию, ракурс, свет, что в кадре. Чужие фото не копировать и не вставлять — только как идея для своего промпта.

## 2. Текст
- RU: `src/content/blog/ru/<slug>.md`, UZ (латиница): `src/content/blog/uz/<slug>.md`, общий `pair`, `draft: true`, `date` — сегодня, `cover: /img/blog/<pair>/<name>.webp`.
- 700–1200 слов. Ответ на вопрос статьи — в первом абзаце. Живой тон «для своих», без воды.
- 3–4 вопроса в `faq`. Внутренние ссылки: прошлые статьи, `/flagi-na-zakaz/` (`/uz/bayroq-buyurtma/`), `/#price` (`/uz/#price`).
- Последний раздел «Как заказать» (UZ «Qanday buyurtma qilish mumkin») и сразу под ним `<div data-order-form></div>`.
- Новое утверждение о компании, которого нет в `knowledge.md`, — не писать, а спросить владельца.

## 3. Картинки (2–3 на статью)
1. Промпт: реалистичное документальное фото, Узбекистан/Ташкент — чинары, панельные дома или одноэтажные постройки, машины Chevrolet Cobalt / Nexia / Gentra / Damas, люди в обычной одежде. Флаги — полотно PLAIN WHITE с оранжевой (#FF6A00) полосой у мачты и по верхнему краю, почти плоско к камере. Без текста, букв и логотипов в кадре.
2. Генерация (по порядку, пока не получится):
   - Figma, команда «dev» — файл `K3q6zyuZLefsYZFxOkBZ2J` (`generate_image`, 1600×900);
   - если «Insufficient Figma AI credits» — команда «tred», файл `RBCWX3I8zfchYRZP9zWUn4`;
   - если и там нет кредитов — Canva `generate-image` (но Canva отдаёт только миниатюру 200 px: если полный размер получить не удалось — написать владельцу, он пришлёт картинки из ChatGPT).
3. Скачать полный размер (`curl -f -L` по `image.url`) → `media-src/blog-raw/<pair>/<name>.jpg` (JPG q92).
4. Посмотреть картинку, найти углы белого полотна флага (по часовой от левого верхнего, ниже изгиба верхнего края) и нанести логотип:
   `node scripts/brand-image.mjs media-src/blog-raw/<pair>/<name>.jpg media-src/blog/<pair>/<name>.jpg --quad x1,y1,x2,y2,x3,y3,x4,y4`
   (несколько флагов — по очереди, `--no-badge` у всех, кроме последнего; классический флаг — `--layout horizontal`). Посмотреть результат.
5. `npm run blog-images` → WebP в `public/img/blog/<pair>/` и обложка для соцсетей.
6. В тексте: `![описание](/img/blog/<pair>/<name>.webp "Подпись")`. Подписи не выдают картинку за реальный заказ конкретного клиента.

## 4. Проверка и сохранение
- `npm run build` и `npm run build:local` без ошибок; открыть статью из `dist-preview` в браузере: картинки, карточки цен, форма на месте.
- В `topics.md` поставить теме [~] и слаги. Коммит и push в `main` (не в `deploy-update`).

## 5. На согласование
- Документ в Claude Docs «Статья на согласование: <тема>»: что проверить (новые утверждения, цифры), RU-версия, UZ-версия, фото (загрузить в документ).
- В чат: ссылка на документ и 2–3 строки — о чём статья и что проверить.

## 6. После «публикуй»
- `draft: false`, `date` — день публикации, правки владельца перенести в md.
- `topics.md`: [x] и дата. `npm run build`, коммит, push в `main` и `main:deploy-update`, дождаться выкладки (`gh run watch`).
- Проверить живые адреса (200, без noindex, есть в sitemap.xml) и прислать ссылки. Карта сайта уже отправлена в Search Console и Яндекс Вебмастер (14.11.2026), новые статьи попадают в неё сами — про отправку sitemap не напоминать. Переобход новых адресов — по желанию владельца, можно упомянуть одной строкой.
